## A1 (2026-11-09T10:40Z) taxonomy redesign after the pilot kill rule failed
Trigger: pilot (240 builds, 111 failures) placed 68/111 = 61.3% of failures in a non-OTHER class; PREREG section "Failure taxonomy" requires >= 80% and says the taxonomy is redesigned before the full run. What the 43 OTHER rows were:

- 6 a package-manager protocol the recipe did not honour (pnpm `workspace:` / `catalog:`, `pnpm: not found`, lerna/yarn monorepos).
- 5 `npm ci` refused (lockfile out of sync with package.json; the log shows only npm's usage text).
- 4 git submodules not fetched (`failed to load manifest for workspace member`, `patch location ... does not contain packages`).
- 4 build-backend / manifest errors (setup.py `extras_require`, `egg_base`, unparseable requirements.txt).
- 3 today's runtime rejecting old code (`primordials is not defined`, `require is not defined in ES module scope`, postinstall script failures).
- 3 refused or failed network fetches not caught by the regexes (proxy 403 through node-gyp/electron-rebuild, `Could not read from remote repository`, uv interpreter download 504, Cypress/phantomjs binary downloads).
- 2 Go "found packages X and Y in the same directory" (a compile-class error the regexes missed).
- 1 other (tsx `skills-npm` missing command at install).

Taxonomy changes (classify_fail.py, regexes to be frozen in recipe rev 2 before the pilot re-run):
1. New class NATIVE-BUILD-FAILED: a C/C++/system step failed for a missing system library or tool after the base toolchain is present (pkg-config "not found", "system library ... was not found", "gyp ERR! not ok", "Command 'make' not found", "Could not find \"cmake\"", "c++: command not found", configure/config.status errors).
2. New class PACKAGE-MANAGER-MISMATCH: the manifest needs a package manager the recipe did not run (`workspace:`, `catalog:`, `pnpm: not found`, `yarn: not found`, `lerna` failures).
3. New class MANIFEST-INVALID: the manifest or build backend rejects the project's own metadata ("The build backend returned an error" with a setup/metadata message; "Couldn't parse requirement").
4. New class RUNTIME-INCOMPAT: today's interpreter rejects the code or its scripts (`primordials is not defined`, `require is not defined in ES module scope`, `ERR_REQUIRE_ESM`, "is not supported" from node/python at run time, postinstall/prepare script exits).
5. DEP-VERSION-CONFLICT gains the npm ci lockfile-sync refusal (match `npm ci` usage text and "package.json and package-lock.json ... are not in sync") and `EOVERRIDE`.
6. NETWORK gains "Request failed after", "Proxy response (403)", "Could not read from remote repository", HTTP 5xx on a toolchain download, `ECONNRESET`, `ETIMEDOUT`; a refused allowlist host anywhere in the log classifies as DEP-MISSING with the host, as the prereg already states.
   Clarification 2026-11-09T11:06Z (before block 2, from the rev-2b illa-builder smoke: pnpm reported `ERR_PNPM_FETCH_403` on a refused host and no string rule matched): the proxy log is the authority for refused-host DEP-MISSING. For every failed build not already TIMEOUT, OOM or NO-MANIFEST, any allowed:false proxy entry in that build's window classifies it DEP-MISSING and the receipt lists the refused hosts (refused_hosts). The string rules ("Proxy response (403)", "farm proxy: host not listed", `ERR_PNPM_FETCH_\d+`) remain as a fallback for builds with no proxy record.
7. COMPILE-ERROR gains Go "found packages ... and ... in" and `go: cannot find main module`.
8. Rule order is fixed and recorded in classify_fail.py: TIMEOUT, OOM, NO-MANIFEST, refused-host DEP-MISSING, NETWORK, PACKAGE-MANAGER-MISMATCH, MANIFEST-INVALID, TOOLCHAIN-EOL, TOOLCHAIN-UNAVAILABLE, NATIVE-BUILD-FAILED, RUNTIME-INCOMPAT, DEP-MISSING, DEP-VERSION-CONFLICT, COMPILE-ERROR, OTHER. The first match wins.
   Corrections 2026-11-09T10:48Z, before any rev-2 commit (raised by research-36): (i) refused-host DEP-MISSING precedes NETWORK, so a build blocked by the allowlist is DEP-MISSING with the host even when the log shows only "Proxy response (403)"; a refused host is a dependency the repo pins outside today's ecosystem, not a transient fault. (ii) DEP-MISSING precedes DEP-VERSION-CONFLICT, because uv reports a missing package inside its "No solution found" resolver text; a missing package named in the log is DEP-MISSING, a conflict between present versions is DEP-VERSION-CONFLICT. Rev-1 pilot counts are unchanged by either (verified by dry reclassification: 14 DEP-MISSING both ways). Left out on purpose: a generic "is not supported" regex (matches npm deprecation warnings) and bare "No such file or directory" panics with no tool named (stay OTHER).

## A8 (2026-11-10T15:42:43Z; corrects the cause stated in A6; recipe rev 2f; no fit or analysis has run; void rule fixed by farm-health evidence, not by build outcomes)

## A10 (2026-11-10T16:31:54Z; second proxy defect; recipe rev 2g; no fit or analysis has run)
Finding: under rev 2f at six parallel builds, containers sat idle for 8 to 11 minutes while the proxy held about 1,460 threads and did not answer a new CONNECT within 40 s. Cause: every connection appended one line to the proxy log by reopening the file under a global lock. Measured inside the proxy container, one append to the bind-mounted log cost 0.207 s at 8.5 MB (0.012 s for a new small file; under 0.001 s on an already open handle). The proxy was therefore limited to a few connections per second, and the limit tightened as the log grew. This throttle existed in every earlier revision and is the likely driver of the descriptor pile-up described in A8; the select limit fixed in rev 2f was real but secondary.
Fix, recipe rev 2g (farm commit cf0fa2eb5ecf998401e3f99c6c42a1f2939bfc94): one writer thread keeps the log open; the previous log is moved aside at proxy start, not deleted. Unchanged: log line format, allowlist, allow and refuse decisions, build recipe, classifier, images, per-build limits. Check (farm/tests/proxy_fd/check.py in the proxy image): tunnel with 1,500 idle sockets PASS; leak PASS (8 descriptors); 400 tunnels from 40 threads in 0.4 s with 401 log lines PASS. On the real proxy with the real bind mount: 150 parallel HTTPS fetches in 2 s, a non-listed host still refused with 403, descriptors back to 5.
Void: all 23 receipts written under rev 2f are void whatever their outcome (kept in OUT/core_void_proxy_20261110/ with prefix v2f__; VOID_LIST_v2f.tsv sha256 e731dc9379927fbe2ad4a54ecdee60046f41b57da6ea218ce37addcce1efd760) and rebuilt under rev 2g. Total void so far: 280 + 28 + 23 + 1 incomplete.

files at that commit, fetched by public GET of raw.githubusercontent.com/<owner>/<repo>/<commit>/<build_dir>/<file>
(no token, no auth header; two tries 600 s apart; still failing = UNFETCHED). It opens no receipt and no log, so it
is outcome-blind. Its output qa/EOL_EXPOSURE.jsonl is produced and sha256-pinned BEFORE the fit.
Parse rules (frozen; fixture tests in qa/tests/test_eol_exposure.py):
- Python: `.python-version` first line, major.minor (patch dropped); else pyproject `project.requires-python` as a
  PEP 440 specifier set: the lowest calendar minor admitted. A set with no lower bound, or only `>=3`, is UNDECLARED.
- Node: package.json `engines.node` npm range (`||`, `>=`, `^`, `~`, `x`, hyphen forms): lowest admitted calendar
  major. `*`, empty or absent = UNDECLARED.
- Go: go.mod `go` directive, major.minor. No go.mod = UNDECLARED.
- Rust: N/A (no end-of-life series).
Calendar: endoflife.date API v1 JSON for python, nodejs, go, downloaded once and sha256-pinned here.
Reference date: wave-0 started 2026-11-09 (CORE_LIST frozen; no receipt read). EXPOSED = cycle EOL before
2026-11-09, or isEol with no date, or older than the oldest calendar cycle when that cycle is EXPOSED; NOT-EXPOSED =
EOL after 2026-11-12 or not yet set. EOL inside the window, or a version newer than every cycle = BOUNDARY.
BOUNDARY, UNDECLARED and UNFETCHED are counted and reported, not imputed.
## Population and outcome
Rows of record (OUT/core_record after step 7), CORE, wave 0, ERA rows for the verdict. Outcome = exit_code 0.
Rows with failure_class TOOLCHAIN-EOL (classifier pattern `^FARM-EOL:`) fail by recipe rule: excluded from the
comparison, their count reported split by EXPOSED status. A19's log-less receipt counts.

## Statistic (fixed)
Verdict statistic, per ecosystem (Python, Node, Go), ERA rows: Mantel-Haenszel risk difference in success share,
NOT-EXPOSED minus EXPOSED, stratified by cohort year (the `cell` year in core/CORE_LIST.jsonl), Sato 95% interval.
A stratum with 0 EXPOSED or 0 NOT-EXPOSED drops out and is counted. Powered = >= 20 EXPOSED and >= 20 NOT-EXPOSED
in the contributing strata; else UNDERPOWERED, no verdict for that ecosystem.
Beside it, labelled descriptive: unstratified RD (Newcombe interval); the NOW-row figures; the share of ERA
failures that are EXPOSED (exact interval); and, per ecosystem, the sensitivity and specificity of "EXPOSED
predicts failure" among the compared ERA rows, each with an exact (Clopper-Pearson) interval.

## Verdict rule (fixed before any outcome is read)
TRACKS: at least 2 of the powered ecosystems have MH-RD >= 10 points with Sato lower bound > 0.
DOES NOT TRACK: at least 2 ecosystems are powered and every powered one has Sato upper bound < 10 points.
Fewer than 2 powered ecosystems: UNDERPOWERED, no verdict. Otherwise INCONCLUSIVE.

## Wording and limits
Results are worded "builds whose declared runtime floor was past end-of-life", never "failed because of end-of-life".
(i) The farm builds Node, Go and Rust on one current toolchain, so EXPOSED measures an old declaration, not an old
runtime in use; for Python the recipe may provision a declared version (not checked here). (ii) A declaration is
a floor, not a need; Python declarations in setup.py or setup.cfg are not read and count as UNDECLARED.
(iii) Cohort stratification removes between-year age differences only, and the analysis makes no causal claim.
(iv) Rust has no calendar. (v) endoflife.date is one third-party source, as published on its download day.

## Order
Tool + tests + calendar hashed -> notarised -> tool run over CORE_LIST, output hashed (before the fit) -> fit go ->
comparison runs after the fit on the rows of record (step 9c slot).

Rule. The H3 verdict computed once by the frozen code (174/369 against 115/205, Fisher two-sided p = 0.0451, SUPPORTED) stays as printed, because changing a frozen classifier after the outcome is known is the move the pre-registration forbids. Beside it, the paper reports, in 6.2 and in the abstract, the count with that one row reclassified as other: 174/368 against 115/206, p = 0.0556. That count does not reject at alpha 0.05. The paper also names the ambiguous chatbot-ui row. The paper states plainly that H3's support rests on one misclassified row and is not robust (see also the post-hoc stratification in 6.7). Any later wave replaces name matching with a tool-account rule, pre-registered before that wave.
