# PREREG (draft, NOT yet notarised): The half-life of popular open-source software
Status: draft 2026-11-09. Binding once hashed into NOTARY.txt after the prior-art TRIAGE is complete. PRIOR-ART: _tools_priorart/dossiers/software_half_life (running).

## Question
What fraction of the most-starred GitHub repositories created in year Y (2013..2024) can be built today from (a) their end-of-(Y+1) snapshot and (b) their current default-branch head, and how does that fraction decay with age per ecosystem?

## Population (frozen before any build; the list file is hashed)
For each Y in 2013..2024 and each ecosystem E in {Python, JavaScript/TypeScript (Node), Go, Rust}: the repositories with the most stars whose GitHub created_at falls in Y and whose primary language is E (GitHub search API, created:Y-01-01..Y-12-31 language:E, sorted by stars, fetched once in monthly slices to clear the 1,000-result cap; non-forks). Two tiers fixed before any build: CORE = the 75 most-starred buildable repos per cell (status OK: an ERA commit exists and an ecosystem manifest or legacy marker is present), drawn from rank <= 100 by stars and extended to rank <= 150 only in cells where rank <= 100 held fewer than 75 (the extended cells are listed in FROZEN_COUNTS.json; a cell still short at 150 keeps what it has and the shortfall is reported), 12 x 4 cells up to 3,600 repos, on which H1-H3 are confirmatory; rows with no ERA commit (NO-ERA), no manifest (NO-MANIFEST) or an unreadable tree (TREE-FAILED) are listed with their status and excluded from every denominator; FULL = the top ~1,000 per cell (about 48,000 repos), on which the same statistics are reported as a pre-registered replication at scale (same recipes, same tests), and whose per-cell results are descriptive. If FULL cannot finish by the analysis date, CORE alone is reported and FULL is labelled incomplete with the finished count. The language query is only the candidate source. A repo's ecosystem is defined by the build manifest present at its ERA snapshot, searched at the root and at depth <= 2: the shallowest manifest wins; among manifests at the same depth the one matching the query language wins; only if none matches does the fixed order Cargo.toml (Rust), go.mod (Go), package.json (Node), pyproject.toml / setup.py / requirements.txt (Python) apply. Primary manifests (Cargo.toml, go.mod, package.json, the Python trio) are searched at depth <= 2; legacy markers at depth <= 1. Legacy manifests count: Go is also identified by Gopkg.toml, Gopkg.lock, glide.yaml, Godeps/Godeps.json, vendor.conf or any *.go file at root or depth <= 1 (flag legacy-go when go.mod is absent; Go modules only exist since Go 1.11, August 2018); Rust is also identified by any *.rs file at root or depth <= 1 when Cargo.toml is absent (flag legacy-rust). Legacy rows stay in the denominator: the recipe attempts the era-appropriate standard build with today's toolchain (GOPATH-mode build for legacy Go; no attempt for pre-Cargo Rust, recorded as TOOLCHAIN-EOL), because "does not build with today's tools" is the outcome under study; a repo whose ERA manifest belongs to another ecosystem than its query language is reassigned to the manifest's ecosystem and counted as drift. Repos with no manifest at the ERA snapshot are recorded as NO-MANIFEST, excluded from every denominator and reported separately; repos with no default-branch commit by the ERA date are NO-ERA, excluded with the reason. Java, C and C++ are out of scope (recipes not deterministic enough) and stated as a limit.

## Snapshots
(a) ERA: the last default-branch commit dated on or before Y+1-12-31. (b) NOW: default-branch head at fetch time. Both fetched once; commit shas recorded.

## Build recipe (one per ecosystem, fixed; container image digest recorded)
- Python: uv venv with the interpreter the project declares (requires-python or .python-version), else the newest stable; uv pip install . (or -r requirements.txt when no package is declared); success = install exits 0 and, when a package is declared, python -c "import <top package>" exits 0.
- Node: Node version from .nvmrc or engines, else current LTS; npm ci when a lockfile exists, else npm install; then npm run build when a build script exists; success = all steps exit 0.
- Go: go build ./... with the toolchain go.mod declares (toolchain directive honoured); success = exit 0.
- Rust: cargo build --locked when Cargo.lock exists, else cargo build; toolchain from rust-toolchain file, else stable; success = exit 0.
Fixed details: the build runs in the directory of the ERA-defining manifest (root or depth <= 2); Python default interpreter when none is declared is CPython 3.13, requires-python specifiers are passed to uv as written; the import check uses the first entry of top_level.txt, else the normalised project name; Node uses engines.node only when it names an exact version, ranges and absence use the current LTS; Go honours the go.mod toolchain directive; Rust honours a rust-toolchain file. Timeout 20 minutes per build, 2 CPUs, 8 GB RAM, network only through an allowlist proxy (pypi.org, files.pythonhosted.org, registry.npmjs.org, nodejs.org, proxy.golang.org, sum.golang.org, storage.googleapis.com, static.crates.io, index.crates.io, static.rust-lang.org, github.com, codeload.github.com, objects.githubusercontent.com, release-assets.githubusercontent.com); every refused host is logged and a build that fails for that reason is DEP-MISSING with the host recorded. Each log records the toolchain actually used (FARM-TOOLCHAIN lines). One attempt, no manual fixes. Every build writes log, exit code and duration; each batch of receipts is signed (DSSE) with the project key.

## Hypotheses (confirmatory)
- H1: ERA build success decreases with age in every ecosystem (Cochran-Armitage trend test per ecosystem, alpha 0.0125, Bonferroni over 4).
- H2: ecosystems differ in half-life. Fit S(age) = exp(-ln2 * age / T) per ecosystem by maximum likelihood on ERA snapshots; report T with a bootstrap 95% CI (1,000 resamples by repo). H2 is supported if the CIs of the best and worst ecosystem do not overlap.
- H3 (secondary): among the 2023-2024 cohorts, repos with AI-assist markers (any commit trailer Co-Authored-By naming Claude, Copilot, Cursor, ChatGPT, Codex or Devin; or a CLAUDE.md, .cursorrules or .github/copilot-instructions.md file at NOW) have lower NOW build success than those without (two-sided Fisher exact test, alpha 0.05). The marker list is frozen here.
Everything else (failure-class shares, star-count effects, per-year tables) is descriptive or EXPLORATORY and labelled so.

## Failure taxonomy (mechanical, from logs; regexes frozen in classify_fail.py before the pilot)
DEP-MISSING, DEP-VERSION-CONFLICT, TOOLCHAIN-UNAVAILABLE (the declared toolchain cannot be obtained today), TOOLCHAIN-EOL (the declared toolchain is end-of-life and no longer installable by the ecosystem's standard version manager, e.g. Python 2), COMPILE-ERROR, NETWORK, TIMEOUT, OOM, NO-MANIFEST, OTHER. Toolchain rule for every recipe: use the version the repository declares if the ecosystem's standard manager (uv, nvm, go toolchain directive, rustup) can still install it today; otherwise the newest stable; a build that fails because neither works is TOOLCHAIN-UNAVAILABLE or TOOLCHAIN-EOL by the regexes. Kill rule: the pilot must place at least 80% of failures in a non-OTHER class, or the taxonomy is redesigned before the full run.
